# Анализ логики работы с несколькими вкладками чата

## Описание проблемы
Проект корректно работает с одной вкладкой чата. При создании второй вкладки и попытке отправки сообщения оно не отправляется, остается "висеть" в чате, и в серверных логах отсутствуют события по второй вкладке.

## Анализ кода

### Клиентская сторона (public/index.html)
- **Создание новой вкладки (`newTab()`)**: 
  - Создается временный ID: `tempId = 'new-' + Date.now()`
  - `currentSessionId = null`
  - `generating = false` для новой вкладки
- **Отправка сообщения (`send()`)**:
  - Проверки: WS подключение, наличие текста/вложений, проект
  - `tabId = activeTabId` (tempId для новой вкладки)
  - `sessionId = currentSessionId || undefined` (null для новой)
  - Если `tabIsGenerating = false`, сообщение отправляется сразу
  - После отправки: `generating = true`, `generatingTabId = activeTabId`

### Серверная сторона (server.js)
- **Обработка сообщения типа 'chat'**:
  - `tabId = msg.tabId || null`
  - Если `tabId` занят (busy), сообщение ставится в очередь
  - Иначе вызывается `processChat(msg)`
- **processChat**:
  - Создает новый `localSessionId` если `sessionId` null
  - Отправляет `session_started` с `sessionId` и `tabId`
  - Миграция состояния с tempId на real sessionId

### Обработчик session_started на клиенте
- Переименовывает вкладку: `tab.id = d.sessionId`
- `activeTabId = d.sessionId`
- `currentSessionId = d.sessionId`

## Гипотезы о причине проблемы

1. **curProjectId не установлен**: Функция `send()` возвращается рано, если `!curProjectId && !currentSessionId`, но очищает input и добавляет сообщение в чат.

2. **WS подключение**: `ws.readyState !== 1` для второй вкладки, сообщение не отправляется.

3. **tabIsGenerating = true**: Несмотря на `generating = false` для новой вкладки, условие срабатывает, сообщение ставится в клиентскую очередь вместо отправки.

4. **Конфликт tabId**: tempId совпадает с существующим sessionId, вызывая путаницу.

5. **currentSessionId не null**: Для второй вкладки `currentSessionId` не сброшен в null, влияет на логику.

6. **Ошибка отправки**: `ws.send()` не выполняется из-за исключения в `JSON.stringify()` или другом месте.

## План исправления

### Шаг 1: Добавить отладку в клиентский код
- В функции `send()` добавить `console.log` перед ключевыми проверками:
  - `console.log('send() start', { wsReady: ws?.readyState, txt: !!txt, attachments: _attachments.length, curProjectId, currentSessionId, activeTabId, tabIsGenerating });`
- После `ws.send()` добавить `console.log('ws.send done');`

### Шаг 2: Проверить серверные логи
- Добавить логи в обработчик 'chat' на сервере:
  - `console.log('[chat] received', { tabId: msg.tabId, sessionId: msg.sessionId, textLen: msg.text?.length });`
- В `processChat` добавить `console.log('[processChat] start', { tabId, sessionId: msg.sessionId });`

### Шаг 3: Проверить переменные состояния
- В `newTab()` добавить логи:
  - `console.log('newTab', { curProjectId, currentSessionId, tempId });`
- В `switchTab()` добавить логи для `currentSessionId`

### Шаг 4: Тестирование
- Создать вторую вкладку
- Проверить консоль браузера и серверные логи
- Попытаться отправить сообщение

### Шаг 5: Исправление на основе логов
- Если `curProjectId` null → проверить логику установки проекта
- Если `tabIsGenerating` true → проверить, почему `generating` не false
- Если WS не подключен → проверить переподключение
- Если сообщение не доходит → проверить JSON или исключения
