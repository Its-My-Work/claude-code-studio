# План исправления отображения Tool Events в UI

## Проблема
В веб-интерфейсе чата tool blocks застревают на статусе "pending" и не обновляются в реальном времени при переходе running → completed. Output инструментов не показывается. Tool block появляется после полного завершения reasoning block вместо параллельного отображения.

## Анализ кода
- Backend (server.js + kilo-agent-backend.mjs) корректно отправляет WebSocket события типа 'ai_chunk' с kind: 'tool' и статусами 'pending', 'running', 'completed', 'failed'
- Фронтенд (index.html) обрабатывает эти события в handleWsMsg case 'ai_chunk' → chunk.kind === 'tool'
- Tool block создается с data-tool-part-id и обновляется при каждом событии
- Логи показывают получение всех событий: pending → running → completed

## Возможные причины (по приоритету)

1. **DOM не перерендеривается при обновлении innerHTML** (наиболее вероятно)
   - При обновлении `toolBlock.innerHTML` браузер может не триггерить reflow
   - Решение: использовать `toolBlock.replaceWith()` или принудительный reflow

2. **Tool block создаётся, но не вставляется в DOM вовремя**
   - Возможно, блок создаётся в памяти, но append() вызывается с задержкой
   - Решение: проверить `messageDiv.appendChild(toolBlock)` вызывается сразу

3. **Race condition при быстрой смене статусов**
   - События приходят быстрее, чем DOM успевает обновиться
   - Решение: использовать requestAnimationFrame() или debounce

4. **Неправильный селектор при поиске существующего блока**
   - `querySelector([data-tool-part-id])` может не находить элемент
   - Решение: добавить логи и проверить `toolBlock !== null`

## Задачи исправления

### 1. Исправить порядок отображения tool и reasoning blocks
- Убедиться, что tool proposal создает tool block сразу при получении 'pending'
- Tool block должен отображаться параллельно с reasoning, а не после него
- Проверить последовательность отправки событий в backend

### 2. Исправить обновление состояния tool block в UI

**Шаг 2.1:** Добавить принудительный reflow после обновления innerHTML:
```javascript
toolBlock.innerHTML = newContent;
void toolBlock.offsetHeight; // принудительный reflow
```

**Шаг 2.2:** Использовать data-атрибуты для состояния:
```javascript
toolBlock.dataset.status = status; // 'pending' | 'running' | 'completed'
```

**Шаг 2.3:** Добавить CSS transitions для плавных изменений:
```css
[data-tool-part-id] {
  transition: background-color 0.2s;
}
[data-tool-part-id][data-status="running"] {
  background-color: #fffbeb;
}
[data-tool-part-id][data-status="completed"] {
  background-color: #f0fdf4;
}
```

**Шаг 2.4:** Проверить, что output рендерится:
```javascript
if (status === 'completed' && chunk.output) {
  const outputEl = document.createElement('pre');
  outputEl.textContent = chunk.output;
  toolBlock.appendChild(outputEl);
}
```

### 3. Добавить логи для отладки WebSocket событий

**Ожидаемые логи в Console:**
```
[TOOL EVENT] pending | bash | prt123abc | input: undefined
[TOOL EVENT] running | bash | prt123abc | input: ls -la
[TOOL DOM] Block created for prt123abc
[TOOL DOM] Block updated: running → input shown
[TOOL EVENT] completed | bash | prt123abc | output: [2048 chars]
[TOOL DOM] Block updated: completed → output shown
```

**Код для логирования:**
```javascript
if (chunk.kind === 'tool') {
  console.log('[TOOL EVENT]', chunk.status, '|', chunk.tool, '|',
              chunk.partId, '| input:', chunk.input?.substring(0,50));

  const toolBlock = document.querySelector(`[data-tool-part-id="${chunk.partId}"]`);
  if (toolBlock) {
    console.log('[TOOL DOM] Block found, updating to:', chunk.status);
  } else {
    console.log('[TOOL DOM] Block NOT FOUND, creating new');
  }
}
```

## Известные ограничения

1. **Быстрая смена статусов** (pending → running за <50ms)
   - DOM может не успеть обновиться между событиями
   - Решение: batching обновлений через requestAnimationFrame

2. **Длинный output** (>10KB)
   - Может тормозить рендеринг страницы
   - Решение: добавить truncation с кнопкой "Показать полностью"

3. **Множественные tool calls параллельно**
   - Нужно убедиться, что каждый tool block уникален по partId
   - Решение: строгая проверка уникальности data-tool-part-id
