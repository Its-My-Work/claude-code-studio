# План реализации KiloAgentBackend

## Обзор
Создать новый класс `KiloAgentBackend` в файле `backends/kilo-agent-backend.mjs`, который будет использовать официальный SDK `@kilocode/sdk` для взаимодействия с локальным сервером Kilo. Класс должен поддерживать потоковую обработку событий, логирование и совместимость с существующим интерфейсом проекта.

## Исследование и подготовка

### 1. Изучить API SDK
- **createKiloClient**: Создает клиент для подключения к серверу Kilo
  - Параметры: `baseUrl`, `directory` (рабочая директория), `signal` (AbortController)
- **client.session.prompt()**: Отправляет запрос в сессию
  - Параметры: `id` (sessionId), `message`, `model`, `maxTurns`, `mcpServers`, etc.
- **client.event.subscribe()**: Подписка на потоковые события
  - Возвращает асинхронный итератор событий
- **client.session.create()**: Создание новой сессии
- **Event types**: `EventMessagePartDelta`, `EventMessageUpdated`, `EventSessionStatus`, etc.

### 2. Определить URL сервера Kilo
- В ENV `KILO_SERVER_URL=http://127.0.0.1:4098`

## Реализация основных функций

### 4. Метод send(options)
- **Входные параметры**: `prompt`, `contentBlocks`, `sessionId`, `model`, `maxTurns`, `abortController`, `cwd`, etc.
- **Формирование полного промпта**: Объединить `prompt` и текстовые блоки из `contentBlocks`
- **Создание/получение сессии**:
  - Если `sessionId` отсутствует, создать новую сессию через `client.session.create()`
  - Установить `title` по первым 100 символам промпта
  - Установить `workdir` = `options.cwd` или `process.cwd()`
- **Отправка запроса**: `client.session.prompt()` с соответствующими параметрами
- **Подписка на события**: `client.event.subscribe()` для потоковой обработки
- **Возврат объекта с колбеками**: `onText`, `onReasoning`, `onTool`, `onDone`, etc.

### 5. Потоковая обработка событий
- **Инициализация подписки**: После отправки промпта запустить `client.event.subscribe()`
- **Обработка типов событий**:
  - `EventMessagePartDelta`: Для текстовых чанков (text/reasoning)
  - `EventMessageUpdated`: Агрегированные обновления
  - `EventToolCall`: Вызовы инструментов
  - `EventSessionStatus`: Изменения статуса сессии
- **Аккумуляция данных**: Собирать `fullText` и `fullThinking`
- **Вызов колбеков**: `onText()`, `onReasoning()`, `onTool()` по мере получения
- **Флаг стриминга**: `hasStreaming` для определения, были ли чанки

### 6. Финализация и фолбек
- **Получение результата**: Ожидать завершения `promptResult`
- **Фолбек для текста**: Если `!hasStreaming`, вызвать `onText()` с полным текстом
- **Вызов onResult**: Передать `promptResult.data` с `subtype`
- **Вызов onDone**: При завершении сессии

### 7. Логирование
- **Генерация requestId**: `uuid.v4()` для каждого запроса
- **Файлы логов**: `logs/{sessionId || 'new'}_{requestId}.log`
- **Формат лога**: JSON строки с `timestamp`, `eventType`, `data`
- **События для логирования**:
  - `request_start`: модель, длина промпта, первые 500 символов
  - `session_created`: новый sessionId
  - `sse_event`: полные JSON события (обрезанные до 4KB)
  - `text_chunk`, `reasoning_chunk`: фрагменты
  - `tool_call`, `tool_result`: инструменты
  - `prompt_response_raw`: полный ответ SDK
  - `request_error`: ошибки

### 8. Обработка abort/timeout
- **AbortController**: При `abortController.abort()` остановить подписку и вызвать `onError`
- **Таймеры**:
  - Короткий фолбек: 10мс после завершения промпта для гарантии `onDone`
  - Длинный таймаут: `this.timeout` мс для защиты от зависаний

### 9. Совместимость и дополнительные методы
- **getStatus()**: Проверить подключение к серверу Kilo
- **setMode(model)**: Установить модель
- **setModel(model)**: То же, что setMode
- **manageSession(sessionId, action)**: Управление сессиями (create, delete, etc.)
