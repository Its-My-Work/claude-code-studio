# План решения проблемы дублирования событий в Kilo AI бэкенде

## Цель
Исправить проблему дублирования событий, которая приводит к повторяющемуся тексту в ответах Kilo AI.

## Анализ проблемы
Проблема прогрессирующего дублирования: с каждым новым сообщением в чате ответ дублируется все больше раз.

**Коренная причина**: Каждый вызов `send()` создает НОВУЮ подписку на поток событий (`/event`), но старые подписки продолжают работать параллельно. Таким образом:
- Первое сообщение: 1 активная подписка → ответ показывается 1 раз
- Второе сообщение: 2 активные подписки → ответ показывается 2 раза
- Третье сообщение: 3 активные подписки → ответ показывается 3 раза

**Дополнительные проблемы**:
- События от сервера приходят дублированными (1-5мс интервал)
- Нет механизма закрытия предыдущих подписок при новом сообщении
- EventSource-подобный стрим остается открытым бесконечно

## Предлагаемое решение
**Решение 1: Управление подписками (Рекомендуется)**
- Использовать единственную подписку на сессию вместо создания новой при каждом сообщении
- Правильно закрывать предыдущие подписки при получении финального ответа
- Добавить механизм прерывания стрима при завершении обработки

**Решение 2: Усиленная дедупликация (Резервный вариант)**
- Глобальный дедупликатор на уровне сессии
- Уникальные ID включают sessionId для предотвращения меж-сессионных конфликтов
- TTL 200мс для учета сетевых задержек

## Шаги реализации (Рекомендуемый подход)
1. **Модифицировать архитектуру подписок**:
   - Добавить управление активными подписками на уровне сессии
   - Закрывать предыдущую подписку при новом сообщении в той же сессии
   - Добавить AbortController для прерывания стрима

2. **Улучшить завершение обработки**:
   - Отписываться от событий при получении `session.turn.close`
   - Очищать ресурсы (reader, buffer) после завершения

3. **Добавить дедупликацию как резерв**:
   - Глобальный EventDeduplicator с sessionId в ключе
   - TTL 200мс для учета задержек

4. **Тестирование**:
   - Создать чат с последовательными сообщениями
   - Проверить отсутствие накопления дубликатов
   - Подтвердить корректное закрытие подписок

## Тестирование
- **Последовательные сообщения**: Отправить 3-5 сообщений подряд в одном чате
- **Мониторинг подписок**: Проверить, что не накапливаются активные стримы
- **Проверка дубликатов**: Убедиться, что каждый ответ показывается ровно 1 раз
- **Корректное завершение**: Подтвердить закрытие подписок после ответа

## Риски
- **Прерывание легитимных событий**: Слишком агрессивное закрытие может оборвать валидные ответы
- **Гонка состояний**: Параллельные сообщения в одной сессии могут конфликтовать
- **Серверные ограничения**: Kilo может не поддерживать множественные одновременные подписки

## Альтернативные решения
1. **Серверная дедупликация**: Запросить исправление в Kilo API
2. **WebSocket вместо SSE**: Переход на двусторонний протокол с явным закрытием
3. **Очереди сообщений**: Буферизация и последовательная обработка вместо параллельной
4. **Глобальный event bus**: Централизованная подписка с маршрутизацией по sessionId
