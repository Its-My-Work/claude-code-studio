# План: Добавление отображения инструментов (tools) в UI чата Kilo

## Цель
Добавить красивое и гармоничное отображение инструментов (tools), которые использует Kilo serve, в UI чата, аналогично тому, как отображаются размышления (reasoning) и ответы (text).

## Анализ текущего состояния
- В UI отлично отображаются размышления (reasoning blocks) и текстовые ответы
- Инструменты (tools) используются Kilo, но не отображаются в чате
- Лог сессии показывает события `step-start`, `reasoning`, `text`, `step-finish`, но не tool events напрямую
- В `server.js` есть обработка tool через callback `onTool`, но в `kilo-agent-backend.mjs` отсутствует вызов этого callback
- В `index.html` есть инфраструктура для отображения tools (`_renderToolLive`, `_renderToolActivity`), но она не используется для Kilo
- Kilo использует Permission Dock для approve/deny инструментов - нужно учитывать состояния: pending, approved, executing, completed
- Структура tool events в Kilo: искать events типа `tool.proposal`, `tool.approved`, `tool.result`
- Важно отображать не только input, но и output инструментов (результаты bash, содержимое файлов, diff)
- Tool blocks должны быть collapsed по умолчанию с возможностью развернуть полный input/output

## Шаги реализации

### 1. Обновление `backends/kilo-agent-backend.mjs`
- Добавить обработку tool events в event loop `processSend`
- Распознать tool parts по `event.type === 'message.part.updated'` с `part.type === 'tool'`
- Обработать lifecycle tool: `tool.proposal`, `tool.approved`, `tool.result`
- Вызывать соответствующие callbacks: `onToolProposal`, `onToolStart`, `onToolComplete`
- Добавить логирование tool events в лог сессии
- Для buffered mode: сортировать tool events по timestamp для правильного порядка

### 2. Обновление `server.js`
- Убедиться, что `onTool` callback для Kilo бэкенда правильно отправляет tool события в WebSocket
- Проверить, что tool события приходят в формате `{ type:'tool', tool:name, input:input }`

### 3. Обновление `public/index.html`
- Добавить новый тип chunk: `tool_chunk` аналогично `reasoning_chunk`
- Создать функцию `_renderToolBlock` аналогично `_renderReasoningBlock`
- Добавить стили для `.tool-block` аналогично `.reasoning-block`
- В обработке `ai_chunk` добавить case для `kind: 'tool'`
- Интегрировать tool blocks в поток сообщений гармонично с reasoning и text
- Добавить состояния tool block: pending, approved, running, completed, failed
- Поддержка collapsed/expanded: по умолчанию collapsed, показать tool name + preview
- Отображение output: результаты инструментов с syntax highlighting, copy buttons
- Анимации для tool execution (spinner/progress)
- Обработка ошибок: error state с красным цветом и error message

### 4. Стилизация
- Сделать tool blocks визуально отличными, но гармоничными с reasoning blocks
- Использовать иконку инструмента (например, гаечный ключ или шестеренка)
- Цветовая схема: нейтральный/серый для tools, синий для reasoning, зеленый для text

### 5. Тестирование
- Проверить отображение tools в разных режимах (native/buffered streaming)
- Убедиться, что tools появляются в правильном порядке относительно reasoning и text
- Проверить на разных типах tools (bash, read, edit, etc.)

### 6. Фазы реализации

#### Фаза 1 (MVP):

## Поведение в разных режимах стриминга

### KILO_STREAM_MODE=native
- **Порядок отображения:** Reasoning → Tools → Text стримятся посимвольно/по частям в реальном времени по мере генерации
- **Tool blocks:** Каждый tool появляется как отдельный блок сразу при вызове, с анимацией стриминга input параметров
- **Визуальный поток:** Плавный поток: reasoning text появляется постепенно, tool blocks всплывают по мере использования, text ответа стримится после

### KILO_STREAM_MODE=buffered
- **Порядок отображения:** Сначала буферизуется весь reasoning, затем все tools, затем весь text ответа
- **Tool blocks:** Все tool blocks появляются одновременно после reasoning, перед text
- **Визуальный поток:** Reasoning появляется целиком → все tools показываются разом → text стримится посимвольно
- **Преимущество:** Пользователь видит полную картину reasoning перед tools, tools перед действием

### Общие аспекты для обоих режимов
- Tool blocks имеют иконку инструмента и краткое описание действия
- Каждый tool block содержит: название инструмента, input параметры (усеченные для читаемости)
- Стилизация гармонична с reasoning blocks (нейтральный цвет, рамка)
- Tool blocks не прерывают поток текста, интегрируются между reasoning и answer

## Ожидаемый результат
- Tools отображаются в чате как отдельные блоки с иконкой, статусом и кратким описанием
- UI остается чистым и не перегруженным благодаря collapsed состояниям
- Tools интегрируются seamlessly в поток reasoning → tools → text
- Пользователь может видеть полный lifecycle tool: от proposal до result
- Интеграция с Permission Dock для approve/deny
- Copy buttons, syntax highlighting, error handling для удобства
